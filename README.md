# 취향 유전자 지도 — 영화판 (배포 테스트 뼈대)

이 폴더 안 파일 4개를 GitHub에 올리고 Vercel에 연결하면, mymangamap.vercel.app과 똑같은 방식으로
`mymoviemap.vercel.app` 사이트가 생깁니다. 아직 지도·매칭 같은 진짜 기능은 없고,
**"검색 → 제출 → 저장 → 목록 보기"가 실제로 되는지**만 확인하는 최소 버전입니다.

## 파일이 하는 일

| 파일 | 하는 일 |
|---|---|
| `index.html` | 방문자가 보는 화면 전체. 영화 검색, 10편 고르기, 이름 적고 제출, 제출 목록 보기 |
| `api/club.js` | "서버" 역할. 카드 저장(POST)과 불러오기(GET) 담당 |
| `api/tmdb.js` | 전 세계 영화 데이터베이스(TMDB) 연결 창구. 검색과 포스터를 가져옵니다 |
| `api/notes.js` | 메모와 도장 저장·조회 |
| `api/blind.js` | 블라인드 게임 기록 저장·조회 |
| `api/duel.js` | 양자택일 집계 저장·조회 |
| `api/eleven.js` | 열한 번째 자리(추천·채택) 저장·조회 |
| `api/_store.js` | 저장소 접속 부품. `_`로 시작해서 주소가 되지 않고 부품으로만 쓰입니다 |
| `movie_dict.json` | 사전 338편 데이터. `index.html`이 이 파일을 읽어서 검색창에 씁니다 |
| `package.json` · `package-lock.json` | `api/club.js`가 저장소에 접속할 때 쓰는 라이브러리 목록 |

> 저장소 접속 방식이 두 가지(REST `https://…` / TCP `rediss://…`)라 둘 다 지원합니다.
> Vercel이 `REDIS_URL` 하나만 넣어줘도, REST 변수만 넣어줘도 알아서 골라 씁니다.

## 올리는 순서

1. **GitHub에서 새 저장소 만들기**
   - github.com 로그인 → 오른쪽 위 `+` → `New repository`
   - 이름 입력 (예: `mymoviemap`) → `Create repository`

2. **이 폴더 파일 그대로 업로드**
   - 방금 만든 저장소 페이지에서 `Add file` → `Upload files` 클릭
   - 이 폴더(`movie-map-starter`) 안의 파일/폴더를 **통째로** 끌어다 놓기
     (`index.html`, `movie_dict.json`, `package.json`, `api` 폴더 전부)
   - 아래 `Commit changes` 버튼 클릭

   ※ GitHub 웹 업로드는 폴더 구조를 그대로 유지합니다.
   `api/club.js`가 `api`라는 폴더 안에 들어있는 채로 올라가야 다음 단계에서 인식됩니다.

3. **Vercel에서 이 저장소 가져오기**
   - vercel.com → GitHub로 로그인 → `Add New` → `Project`
   - 방금 올린 저장소 선택 → `Deploy`
   - Framework Preset은 `Other`로 두면 됩니다 (Vercel이 `api/` 폴더를 자동으로 인식합니다)

4. **Storage 연결 (Upstash Redis)**
   - 배포된 프로젝트 페이지 → 상단 `Storage` 탭 → `Browse Marketplace`
   - `Upstash for Redis` 선택 → 이 프로젝트에 연결
   - 연결하면 비밀번호 같은 값이 자동으로 프로젝트에 들어갑니다 (직접 입력할 필요 없음)

5. **재배포**
   - Storage를 4번에서 새로 연결했다면, `Deployments` 탭에서 최신 배포 옆 `···` → `Redeploy` 한 번
   - 끝나면 `mymoviemap.vercel.app` 접속 → 검색해서 영화 몇 편 고르고 제출 → 아래 목록에 뜨면 성공

## 화면 구성

두 개의 탭으로 나뉩니다.

- **01 카드 내기** — 네 단계로 내 인생 영화 열 편을 제출합니다.
- **02 클럽 보기** — 다른 사람의 입장권을 보고, **포스터를 눌러 메모를 남깁니다.**
- **03 놀이** — 게임 두 가지. **블라인드**(누구의 카드인지 맞히기)와 **양자택일**(둘 중 하나 고르기).
- **04 취향 지도** — 클럽 전체가 좌표 위에 놓이고, **내 취향 쌍둥이**가 근거와 함께 나옵니다.

### 이미 낸 카드를 고치려면
「카드 내기」 맨 위 **「이미 낸 적이 있다면」**에서 내 이름을 누르면 됩니다.

- 이름을 누르면 **바로** 불러옵니다. 골랐던 열 편, 감정 위치, 태그, 이름, 한 줄이 그대로 다시 채워집니다.
- 화면 맨 위에 **누구의 카드를 고치는 중인지** 금색 띠로 계속 표시됩니다.
- 제출 버튼이 「고친 카드 내기」로 바뀌고, 내면 **먼저 낸 카드를 덮어씁니다.** 새 카드가 하나 더 생기지 않습니다.
- 잘못 눌러도 **다시 내기 전에는 아무것도 바뀌지 않습니다.** 「새 카드로 시작」으로 빠져나오면 됩니다.
- 이미 이 브라우저에서 카드를 낸 사람은 「클럽 보기」의 자기 카드에 있는 **「이 카드 고치기」** 버튼이 더 빠릅니다.
- **부캐를 새로 만들 때도** 「새 카드로 시작」을 누르고 시작하면 됩니다.

기기를 바꿨거나 브라우저 기록을 지워서 "내 카드가 사라진 것처럼" 보일 때도 같은 방법으로 되찾습니다.
카드는 서버에 그대로 있고, 이 브라우저가 내 것인 줄 모르는 상태일 뿐입니다.

### 이름만 바꾸기
카드를 불러온 뒤 금색 띠의 **「이름만 바꾸기」**를 누르면 됩니다.
고른 열 편·메모는 그대로 두고 이름만 바꿉니다.

이름은 카드에만 있는 게 아니라 **메모·도장·블라인드 기록·열한 번째 자리 추천**에도 박혀 있습니다.
한 군데만 고치면 나머지가 옛 이름을 가리키는 미아가 되므로, **전부 함께 옮깁니다.**
이미 쓰고 있는 이름으로는 바꿀 수 없습니다.

### 카드 지우기 — 확인 두 번
**「이 카드 지우기」**를 누르면 두 단계를 거칩니다. 되돌릴 수 없기 때문입니다.

1. **무엇이 함께 사라지는지** 숫자로 보여줍니다 (영화 몇 편, 메모 몇 건, 도장, 추천, 블라인드 기록).
2. **카드 이름을 직접 타이핑**해야 「영구 삭제」가 동작합니다.

서버도 받은 이름과 확인용 이름을 한 번 더 대조합니다. 화면 코드가 잘못되어도 실수로 지워지지 않습니다.

지우면 **그 이름에 달린 것이 전부** 사라집니다 — 카드, 그 카드에 붙은 메모,
그 이름으로 남긴 메모와 도장, 받은·보낸 추천, 블라인드 기록.
남의 카드와 남의 메모는 건드리지 않습니다.

### 메모는 '한 편의 영화'에 붙습니다
카드 전체가 아니라 특정 영화에 붙습니다. 그래야 할 말이 생깁니다.

- **메모** — 포스터를 누르면 그 영화에 대한 메모창이 열립니다. 붙은 메모 수가 포스터 위 금색 배지로 표시됩니다.
- **도장** — 글쓰기가 부담될 때 누르는 원탭 반응 세 가지: `나도` / `이건 봐야겠다` / `의외다`. 다시 누르면 취소됩니다. 눌린 흔적이 포스터 아래 금색 띠로 남습니다.
- **작품 뒷면** — 메모창의 `작품 뒷면 →`을 누르면 그 영화 하나에 대한 모든 것이 모입니다. 누가 골랐는지, 카드 경계를 넘어 붙은 모든 메모.

메모를 쓰려면 이름이 필요합니다. 카드를 제출했다면 그 이름이 자동으로 쓰이고,
아직 안 냈다면 「클럽 보기」 상단에서 이름을 한 번 알려주면 됩니다.

### 블라인드 — 이 열 편은 누구의 것인가
만화판에 있던 그 게임입니다. 카드가 3장 이상 모이면 열립니다.

- 이름·한 줄·태그를 가린 채 **포스터 열 장과 통계만** 보여줍니다.
- 다섯 명 중에서 고르고, 10문제를 풉니다. 최고 기록이 남습니다.
- 8문제 이상 맞히면 **감별사**입니다.
- 게임이 끝나면 **정체를 가장 잘 숨긴 사람** 순위가 나옵니다. 클럽 전체의 기록이 쌓여서 만들어집니다.

이름을 알려주지 않아도 게임은 할 수 있고, 그때는 최고 기록만 안 남습니다.

### 양자택일 — 둘 중 하나만 남긴다면
두 편을 놓고 하나 고르는, 3초짜리 놀이입니다. 카드를 안 낸 사람도 참여할 수 있습니다.

- 후보는 **여러 명이 인생작으로 꼽은 작품**을 우선합니다. 풀이 넓으면 표가 흩어져 순위가 안 생깁니다.
- 고르면 곧바로 **클럽이 어떻게 갈렸는지** 막대로 보여줍니다.
- 2표 이상 모인 작품부터 **「클럽이 고른 최강」** 순위에 들어갑니다.

### 열한 번째 자리 — 남이 채워주는 한 칸
카드 맨 끝에 빈 칸이 하나 있습니다. **다른 사람이 권해서 채우는 자리**입니다.

- 남의 카드 끝 빈 칸을 누르고, 영화를 골라 **왜 이 사람에게 이 영화인지** 한 줄과 함께 권합니다.
- 한 사람에게는 한 편만 권할 수 있습니다. 바꾸려면 거두고 다시 권하세요.
- **채택은 카드 주인만** 할 수 있습니다. 채택되면 그 자리에 포스터가 걸리고 **추천한 사람 이름이 함께 박힙니다.**
- 열한 번째는 통계와 유사도 계산에는 들어가지 않습니다. 내가 고른 열 편과는 성격이 다르니까요.

### 취향 지도 — 같은 영화를 안 골라도 이어집니다
카드를 다섯 층(작품 / 감독 / 장르 / 성향 / 국가·연대)으로 나눠 비교합니다.
인원이 적을수록 작품 비중을 낮추고 감독·연대 비중을 올려서, 겹치는 영화가 없어도 연결됩니다.

- 세로는 대중↔니치, 가로는 마음이 데워짐↔부서짐.
- 작은 점이 영화 한 편(여러 명이 고를수록 커짐), 이름 붙은 큰 점이 그 사람의 한가운데.
- 쌍둥이에는 **왜 비슷한지 문장**이 붙습니다 — "박찬욱을 각각 다른 작품으로 좋아하고 계십니다 — 올드보이 / 친절한 금자씨."

## 영화 검색·포스터 켜기 (TMDB 열쇠)

이걸 안 해도 사이트는 돌아갑니다. 내장 사전 338편으로만 검색되고 포스터가 안 붙을 뿐입니다.
열쇠를 꽂으면 **전 세계 영화가 검색되고, 검색 결과에 포스터가 바로 뜹니다.**

1. [themoviedb.org](https://www.themoviedb.org) 가입 → 이메일 인증
2. 오른쪽 위 프로필 → `Settings` → 왼쪽 메뉴 `API` → `Request an API Key`
3. 종류는 `Developer` 선택. 용도는 간단히 적으면 됩니다
   (예: 사내 소모임에서 취향 매칭용으로 쓰는 비영리 웹앱)
4. 승인되면 나오는 **API Key (v3 auth)** 문자열을 복사
5. Vercel 프로젝트 → `Settings` → `Environment Variables` →
   - Key: `TMDB_KEY`
   - Value: 복사한 문자열
   - 저장
6. `Deployments` 탭 → 최신 배포 옆 `···` → `Redeploy`

확인: `https://mymoviemap.vercel.app/api/tmdb?diag=1` 을 열어 `"열쇠_꽂힘": true` 가 나오면 켜진 겁니다.

> 열쇠를 꽂으면 **사전에 없는 영화도 감독과 연도를 자동으로 받아옵니다.**
> 취향 지도의 「같은 감독」·「같은 연대」 층이 사전 밖 작품까지 읽으려면 이게 필요합니다.
> 열쇠가 없으면 사전 338편 밖의 작품은 제목만 남고 감독·연대 비교에서 빠집니다.

> 열쇠는 Vercel에만 저장되고 방문자에게는 절대 보이지 않습니다.
> 브라우저는 `api/tmdb.js`에게 물어보고, 그 파일만 TMDB에 접속합니다.
>
> TMDB 무료 사용 조건상 화면 어딘가에 출처를 밝히는 것이 권장됩니다.
> 사내 비영리 용도라면 보통 문제없지만, 공개 배포 전에는 약관을 한 번 확인하세요.

### 포스터는 한 번만 찾습니다
한 번 찾은 포스터 주소는 저장소에 기록해 두고 다음부터는 다시 묻지 않습니다.
30명이 각각 10편을 올려도 TMDB 호출은 수백 번 수준이라 무료 한도에 한참 못 미칩니다.

없는 포스터는 **화면에 그리는 그 자리에서 바로 요청합니다.** 클럽·놀이·지도 어디서든 같습니다.
TMDB 번호를 아는 작품은 **번호로 곧장** 가져오므로 제목을 잘못 짚을 일이 없습니다.

### 「수면 아래 작품」은 어떻게 세나요
카드 아래 통계 중 하나로, **얼마나 덜 알려진 작품을 골랐는가**입니다.

- 사전 338편은 손으로 매긴 대중값을 씁니다.
- 사전 밖 작품은 **TMDB 표 수**로 판단합니다. 클럽이 고른 작품은 대부분 사전 밖이라 이게 없으면 전원 0이 됩니다.
- 판정 기준은 **보정 표 수 400 미만**입니다. 한 칸 좁혀 둔 값이라 어지간히 알려진 작품은 대중 쪽으로 갑니다.
- 표 수는 나라마다 자릿수가 달라서 (TMDB는 영어권 이용자가 많습니다) **제작국별로 보정**한 뒤 잽니다.
  보정이 없으면 천만 영화 「파묘」도 수면 아래로 잡힙니다.
- 알려진 정도를 아직 모르는 작품은 **세지 않습니다.** 잘못 세는 것보다 낫습니다.
  TMDB 열쇠가 꽂혀 있으면 클럽 화면을 열 때 자동으로 채워집니다.

실제 확인값 — 겨울왕국(US) 17,857표 · 올드보이(KR) 10,165표 · 파묘(KR) 801표 ·
혐오스런 마츠코의 일생(JP) 188표 · 윤희에게(KR) 66표.
앞의 셋은 대중, 뒤의 둘은 수면 아래로 잡힙니다.

#### 연도표가 곧 수면입니다
카드 아래 연도표의 가로선이 수면입니다.

- **선 위 채운 점** — 널리 알려진 작품
- **선 아래 빈 원** — 수면 아래 작품. 몇 년대에 잠겨 있는지 한눈에 보입니다.
- **점을 누르면** 제목과 연도가 바로 아래에 뜨고, **위 포스터에서 그 자리가 금색으로 빛납니다.**

연도·감독은 카드에 저장된 값을 먼저 씁니다. 사전에만 기대면 사전 밖 작품이
연도표에서 통째로 빠져서, 연대 폭과 취향 중앙값까지 어긋납니다.

### 포스터가 엉뚱한 영화로 붙었을 때
「사도」처럼 짧고 흔한 제목은 검색 첫 줄이 다른 영화일 수 있습니다.
그래서 **원제와 연도를 함께 걸어 찾고, 맞는지 검증한 뒤**에 붙입니다.
확신이 없으면 **틀린 포스터 대신 빈 자리로 둡니다.** 틀린 포스터가 빈 자리보다 나쁘니까요.

그래도 이미 잘못 박힌 게 있다면 주소창에 아래를 입력해 지우면 됩니다.
지운 뒤 사이트를 새로고침하면 새 방식으로 다시 찾습니다. **카드·메모·기록은 그대로입니다.**

```
https://mymoviemap.vercel.app/api/tmdb?repair=사도        ← 그 작품만
https://mymoviemap.vercel.app/api/tmdb?repair=1           ← 전부 다시 찾기
```

### 클럽이 겹친 지점 (클럽 보기 상단)
**두 명 이상이 같이 고른 작품** 세 편을 포스터와 함께 보여줍니다.
누른 사람 이름이 같이 적히고, 누르면 그 작품의 **작품 뒷면**이 열립니다.
겹치는 작품이 하나도 없으면 이 영역은 아예 나오지 않습니다.

## 올린 게 진짜 올라갔는지 확인하기

파일을 올렸는데 달라진 게 없어 보이면, **대개 파일이 아직 안 올라간 것**입니다.
(GitHub 웹 업로드에서 `api` 폴더가 빠지는 일이 자주 있습니다.)
아래 두 주소를 열어 **버전이 같은지** 보세요.

```
https://mymoviemap.vercel.app/api/club?diag=1     → "버전": "2026-09-11-a"
https://mymoviemap.vercel.app/api/tmdb?diag=1     → "버전": "2026-09-11-a"
```

화면 쪽 버전은 사이트 맨 아래 회색 작은 글씨(`화면 버전 …`)에 있습니다.
**셋이 모두 같아야** 새 기능이 도는 상태입니다. 하나라도 다르거나 `버전` 항목이 아예 안 보이면
그 파일이 예전 것이니, 압축을 푼 폴더를 통째로 다시 올리고 배포가 끝날 때까지 기다리세요.

## 안 될 때 — 먼저 진단 주소를 열어보세요

브라우저 주소창에 이렇게 입력하면 저장소 연결 상태를 알려줍니다.
(비밀키 **값**은 절대 표시되지 않고, 변수 **이름**만 보여줍니다.)

```
https://mymoviemap.vercel.app/api/club?diag=1
```

- `"연결됨": true` → 정상. 그래도 제출이 안 되면 `Deployments` 탭에서 Redeploy 한 번.
- `"연결됨": false` 이고 `발견된_저장소_관련_변수이름`이 **빈 목록** → Storage 연결(4번)이 안 된 상태입니다.
- `"연결됨": false` 인데 변수 이름은 여러 개 보임 → 이름이 예상과 다른 경우입니다. 그 목록을 알려주시면 맞춰 드리겠습니다.

### 자주 나오는 증상

| 증상 | 원인 |
|---|---|
| `Failed to parse URL from /pipeline` | 저장소 접속 주소가 비어 있음 = Storage 미연결 또는 Redeploy 안 함 |
| 화면은 뜨는데 검색이 안 됨 | `movie_dict.json`이 `index.html`과 같은 위치(루트)에 없음 |
| 제출 버튼이 계속 회색 | 버튼 아래 "남은 것 —" 줄에 무엇이 부족한지 표시됩니다 |
